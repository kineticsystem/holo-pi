## Introduction

This document describes the HTTP API of `holo-pi serve`, the server that shows quilts and videos on a Looking Glass. It assumes we have read [Use HoloPi](../README.md#use-holopi) in the README.

The server listens on port 8095, e.g. `http://holo.local:8095`, where it serves its web page on `/` and the API on `/api`. It documents the API itself, generated by FastAPI from the code:

| Page | What it is |
|---|---|
| `/api/docs` | Swagger UI: every request, with its fields, its answers and examples, and a form to try it. Its files are the server's own, so it works on a network without the internet. |
| `/api/openapi.json` | The OpenAPI 3 description, to generate a client. |

The API has three main resources. The **media** are the quilts and videos kept in the server's library, on its disk; the **playlist** says which of them play one after the other, and for how long; the **display** is what the Looking Glass shows. A medium is uploaded once, and shown as often as wanted, by its id or its name, at once.

Requests and answers are JSON, except the upload, a multipart form, and a medium's content, its file. There is no authentication: keep the server on a network you trust. **Try it out**, in Swagger UI, changes what the Looking Glass shows and the library on its disk.

## The Media

### Upload a Medium

```
POST /api/media
Content-Type: multipart/form-data
```

The server keeps the file in its library and answers with the [medium](#the-medium): `201 Created`, with its address in `Location`, e.g. `/api/media/3f9a1c2e`, or `200 OK` if it replaced the medium of the same name, whose id it keeps. A name is unique in the library, so that it addresses a medium as its id does.

| Field | Type | Default | What it is |
|---|---|---|---|
| `file` | file | required | The quilt or the video: an image Pillow reads, or a video FFmpeg reads. |
| `columns` | integer, 1 or more | from the name | Its columns of views, when its name does not say, e.g. 8. With `rows`, or not at all. |
| `rows` | integer, 1 or more | from the name | Its rows of views, when its name does not say, e.g. 6. |
| `reverse` | boolean | `false` | Shows its views in the other order, when the depth looks inside out. |
| `play` | boolean | `false` | Shows it at once, too, as [`PUT /api/display`](#show-a-medium-the-test-pattern-or-the-playlist) would. The answer's `shown` says whether it is on the screen; `GET /api/display` says why not, e.g. the Looking Glass is off, and the server shows it as soon as it can. |

A medium is of one of three kinds:

- **A quilt,** an image of a grid of views, of the layout its name gives, as Looking Glass's tools read it, e.g. `_qs8x6a0.75` for 8 columns, 6 rows, views of aspect 0.75, or the fields `columns` and `rows`. A Portrait's quilt is usually 8 x 6 views, view 0 at the bottom left, rows from the bottom up.
- **A quilt video,** a video with a layout, whose every frame is a quilt. The GPU interleaves each frame as it is shown, up to about 25 frames per second on a Raspberry Pi 5. It plays on any Looking Glass.
- **A hologram video,** a video without a layout, interleaved already for this Looking Glass, as the videos a Portrait keeps on its own drive, e.g. `Anna.jpg__lkgrec.mp4`. The server shows its frames as they are, so a video made with another Looking Glass's calibration shows a blur. A frame is the screen's size, 1536 x 2048 for a Portrait, or twice as wide, 3072 x 2048, as a Portrait's own videos, whose every pixel of the screen is two pixels side by side; the server shows one pixel of each two.

The server decodes with FFmpeg, through PyAV: with the Pi 5's hardware decoder for H.265 (HEVC), in the container on a Pi, and on the processor otherwise. A video of another codec comes with a `warning`, which says how to encode it again.

| Status | When | Body |
|---|---|---|
| `201` | The medium is new. | The [medium](#the-medium). |
| `200` | It replaced the medium of the same name, and kept its id. | The [medium](#the-medium). |
| `400` | Not an image nor a video, a quilt of no layout, only one of `columns` and `rows`, or a hologram video not of the screen's size or twice its width. | An [error](#errors). The library does not change. |
| `422` | A field of the wrong type, e.g. `columns=eight`, or no `file`. | An [error](#errors). |
| `501` | A video, and the server has no PyAV, `python3-av`. | An [error](#errors). |

### The Medium

```json
{
  "id": "8299c881",
  "name": "helix_qs8x6a0.75.mp4",
  "kind": "quilt video",
  "size": 122438702,
  "uploaded": "2026-11-17T13:20:05+00:00",
  "width": 3360,
  "height": 3360,
  "columns": 8,
  "rows": 6,
  "reverse": false,
  "fps": 24.0,
  "frames": 480,
  "duration": 20.0,
  "codec": "hevc",
  "warning": null,
  "grade": null,
  "shown": true
}
```

| Field | What it is |
|---|---|
| `id` | What addresses it: `/api/media/{id}`, and `PUT /api/display`. |
| `name` | Its file's name, as uploaded: unique in the library. |
| `kind` | `quilt`, `quilt video` or `hologram video`. |
| `size` | Its file's size, in bytes. |
| `uploaded` | When it was uploaded, in UTC, ISO 8601. |
| `width`, `height` | Its size, or its frames', in pixels. |
| `columns`, `rows` | Its layout; `null` for a hologram video. |
| `reverse` | Whether its views are shown in the other order. |
| `fps`, `frames`, `duration` | A video's frames per second, number of frames and length in seconds, if its file says; `null` for a quilt. |
| `codec` | How a video is encoded, e.g. `hevc`; `null` for a quilt. |
| `warning` | What to change, for a video not in H.265, or `null`. |
| `grade` | Whether a quilt is [graded](#the-grades): `"on"`; `"off"`, shown as uploaded, with its values kept; or `null`, not graded, as every video. |
| `shown` | Whether the Looking Glass shows it now. |

### List the Media

```
GET /api/media
```

```json
{"items": [{"id": "8299c881", "name": "helix_qs8x6a0.75.mp4", "...": "as in The Medium"}],
 "size": 431400000, "free": 230600000000}
```

| Field | What it is |
|---|---|
| `items` | The [media](#the-medium), in the library's order: as uploaded, a new one last, unless [`PUT /api/media/order`](#order-the-media) changed it. |
| `size` | The bytes they take, together. |
| `free` | The bytes left on the disk, for more. |

### Order the Media

```
PUT /api/media/order
Content-Type: application/json
```

```json
{"ids": ["8299c881", "3f9a1c2e", "c41d07aa"]}
```

Puts the library in the order of `ids`, every id of the library once, and answers the [list](#list-the-media) as it is now. The web page shows the media in this order, and moves a row when we drag it by its grip. The server keeps the order in `index.json`, so it stays after a restart. A new upload goes last; an upload that replaces a medium of the same name keeps its place.

The whole order goes in each request, not one move, so that sending it twice changes nothing. A list made before another client uploaded or removed a medium no longer has every id, and the server refuses it rather than guess where the others go: the client reads the list again.

| Status | When | Body |
|---|---|---|
| `200` | The library is in this order. | The [list](#list-the-media). |
| `400` | An id twice, or one of the library's left out. | An [error](#errors). The order does not change. |
| `404` | An id the library does not have. | An [error](#errors). The order does not change. |

### Get, Download and Remove a Medium

```
GET /api/media/{id}
GET /api/media/{id}/content
DELETE /api/media/{id}
```

`GET /api/media/{id}` answers the [medium](#the-medium); `GET /api/media/{id}/content` its file, as uploaded, with its name in `Content-Disposition`:

```bash
curl -OJ http://holo.local:8095/api/media/8299c881/content
```

`DELETE /api/media/{id}` removes it from the library, its file too, and answers `204`, with no body. If the Looking Glass shows it, it shows black. All three answer `404` for an id the library does not have.

### Rename a Medium

```
PUT /api/media/{id}/name
Content-Type: application/json
```

```json
{"name": "my helix_qs8x6a0.75.mp4"}
```

Gives the medium another name, and answers the [medium](#the-medium). Its file, its id, its layout, its grade and its place in the library stay, and what the Looking Glass shows does not change. A layout in the new name is only text: the medium keeps the one it was uploaded with. The name keeps its file's extension: `my helix` becomes `my helix.mp4`.

| Status | When | Body |
|---|---|---|
| `200` | The medium has this name. | The [medium](#the-medium). |
| `400` | A name no file can have: empty, longer than 255 bytes, or with a slash, a backslash or a control character. | An [error](#errors). |
| `404` | An id the library does not have. | An [error](#errors). |
| `409` | Another medium has this name. | An [error](#errors). Nothing is replaced. |

### Remove Every Medium

```
DELETE /api/media
```

Empties the library, its files too, and answers `204`. If the Looking Glass shows one of them, it shows black.

## The Grades

A grade is how a quilt's light and colours are changed when it is shown: exposure, contrast, saturation, sharpness, and so on, the tools of StepIt Grader. It is kept beside the quilt, in the library's index, and the quilt's file stays as uploaded. Only quilts can be graded, not videos, and only a screen drawn by the GPU, `--screen gl`, the container's, shows grades.

### Grade a Quilt

```
GET /api/media/{id}/grade
PUT /api/media/{id}/grade
DELETE /api/media/{id}/grade
```

```bash
curl -X PUT -H "Content-Type: application/json" -d '{"exposure": 0.5, "saturation": 20, "sharpness": 60}' http://holo.local:8095/api/media/8299c881/grade
```

`PUT` replaces the whole grade: a value not given is at its default. If the Looking Glass shows the quilt, it answers once the quilt is drawn with the grade, about 14 ms later on a Pi 5, or about 31 with a tool that looks around each pixel: a client can send one request after another to follow a slider. If the quilt cannot be shown yet, the grade is kept, and `GET /api/display` says why. It answers the grade, as `GET` does: every value, and `enabled`, which when `false` shows the quilt as uploaded and keeps the values. The [medium](#the-medium) says in its `grade` whether it has one, so that a client can mark the graded quilts of a list without a request for each.

The server writes the grade to its disk a second after the last change, and it stays after a restart. An upload that replaces a medium of the same name has no grade. `DELETE` puts every value back to its default and answers `204`, with no body.

| Status | When | Body |
|---|---|---|
| `200` | The quilt has this grade. | The grade. |
| `400` | A video: only a quilt can be graded. | An [error](#errors). |
| `404` | An id the library does not have. | An [error](#errors). |
| `422` | A value out of its range, e.g. `{"exposure": 9}`. | An [error](#errors). |
| `501` | The screen is not drawn by the GPU. | An [error](#errors). |

### Save a Graded Quilt

```
POST /api/media/{id}/graded-copies
```

Keeps the quilt with its grade as a new quilt, the last of the library, and answers `201` with its `Location`, `/api/media/{id}` of the new one, and the [medium](#the-medium). The request has no body: it saves the grade the server has. The new quilt is a PNG, without loss, of the same size, layout and order of views, whose name gets `-graded` before its layout, e.g. `helix-graded_qs8x6a0.75.png`, then `helix-graded-2_qs8x6a0.75.png`: it never replaces another. It has no grade of its own, as it is in its pixels, and any Looking Glass can show it. The quilt, its grade and what the Looking Glass shows do not change.

| Status | When | Body |
|---|---|---|
| `201` | The new quilt is in the library. | The [medium](#the-medium). |
| `400` | A video, or a quilt that has no grade, or whose grade is switched off. | An [error](#errors). |
| `404` | An id the library does not have. | An [error](#errors). |
| `501` | The screen is not drawn by the GPU. | An [error](#errors). |
| `503` | The Looking Glass is not ready: the GPU draws only with its screen. | An [error](#errors). |

### The Parameters

```
GET /api/grade-parameters
```

Answers the values of a grade, `items`, section by section, in the order to show them; the web page draws its sliders from it:

```json
{"items": [{"id": "exposure", "label": "Exposure", "section": "Light", "description": "The light, in stops: 1 is twice as much.",
            "minimum": -5, "maximum": 5, "default": 0, "decimals": 2}]}
```

| Section | Parameters |
|---|---|
| Color | `temperature`, `tint`, `vibrance`, `saturation` |
| Light | `exposure`, in stops, `contrast`, `highlights`, `shadows`, `blacks` |
| Tone Curve | `curve_shadows`, `curve_darks`, `curve_lights`, `curve_highlights`, and where these zones meet, `shadow_split`, `midtone_split`, `highlight_split` |
| Color Mixer | `<band>_hue`, `<band>_saturation`, `<band>_luminance`, for the bands `red`, `orange`, `yellow`, `green`, `aqua`, `blue`, `purple` and `magenta` |
| Effects | `structure`, `detail`, `sharpness` |

## The Playlist

The playlist says which media of the library play one after the other, and for how long each: a quilt is shown for some seconds, a video plays some times over. They play in the library's order, see [Order the Media](#order-the-media). `PUT /api/display` with `{"playlist": true}` plays it.

### Get the Playlist

```
GET /api/playlist
```

```json
{
  "repeat": true,
  "transition": "cross fade",
  "transition_seconds": 1.0,
  "items": [
    {"media_id": "b44ef8ba", "enabled": true, "seconds": 15.0, "loops": null},
    {"media_id": "8299c881", "enabled": true, "seconds": null, "loops": 2},
    {"media_id": "c41d07aa", "enabled": false, "seconds": null, "loops": 5}
  ]
}
```

| Field | Default | What it is |
|---|---|---|
| `repeat` | `true` | Whether it starts again after the last medium. Otherwise it ends, and the Looking Glass shows black. |
| `transition` | `cut` | How one medium goes into the next: `cut`, at once, `cross fade`, `fade through black`, `wipe`, from the left, `iris`, from the middle, or `dissolve`, in squares. The GPU draws it: without it, i.e. not with `--screen gl`, the playlist always cuts. |
| `transition_seconds` | `1` | How long a transition takes, 0.1 to 10. These are the first seconds of the next medium, not added to its own. |
| `items` | | The media, in the library's order. One that is not among them is not played. |
| `media_id` | | The medium. |
| `enabled` | `true` | Whether it is played: `false` keeps its settings only. |
| `seconds` | `10` | How long a quilt is shown, 1 to 86400; `null` for a video. |
| `loops` | `1` | How often a video plays before the next medium, 1 to 1000; `null` for a quilt. |

The playlist is empty at first. A medium removed from the library leaves it.

### Set the Playlist

```
PUT /api/playlist
Content-Type: application/json
```

The body is a playlist, which replaces the one before, e.g. a quilt for 15 seconds, then a video twice:

```json
{"items": [{"media_id": "b44ef8ba", "seconds": 15}, {"media_id": "8299c881", "loops": 2}]}
```

What the Looking Glass shows does not change. While the playlist plays, the change counts from the next medium on; with nothing left to play, it ends.

| Status | When | Body |
|---|---|---|
| `200` | It is kept, also after a restart. | The playlist. |
| `400` | A medium is given twice, `seconds` for a video, or `loops` for a quilt. | An [error](#errors). |
| `404` | No medium of an id. | An [error](#errors). |

## The Display

### What Is Shown

```
GET /api/display
```

```json
{
  "source": "media",
  "media": {"id": "8299c881", "name": "helix_qs8x6a0.75.mp4", "...": "as in The Medium"},
  "name": "helix_qs8x6a0.75.mp4",
  "kind": "quilt video",
  "reverse": false,
  "shown": true,
  "shown_on": "HDMI-A-1 of /dev/dri/card1, 1536 x 2048, through the GPU",
  "error": null,
  "frame_rate": 23.4,
  "decoder": "hardware",
  "warning": null,
  "playlist": {"position": 2, "count": 5}
}
```

| Field | What it is |
|---|---|
| `source` | Where what is shown comes from: `media`, the library; `test pattern`; `default`, the server's default quilt, `--default-quilt`; or `null`, black. |
| `media` | The [medium](#the-medium) shown, if it comes from the library. |
| `name` | The name of what is shown, `numbers` for the test pattern. |
| `kind` | `quilt`, `quilt video` or `hologram video`. |
| `reverse` | Whether its views are shown in the other order. |
| `shown` | Whether it is on the Looking Glass now: `false` while the Looking Glass is unplugged or off. |
| `shown_on` | Where: the screen through the GPU, e.g. `HDMI-A-1 of /dev/dri/card1, 1536 x 2048, through the GPU`, through DRM/KMS, or the desktop's monitor, e.g. `the monitor at 3840, 0, 1536 x 2048`. |
| `error` | Why it is not shown yet, e.g. `no Looking Glass found`. The server tries again every 5 seconds. |
| `frame_rate` | A video's frames shown a second, lately: its `fps` when the server keeps up, less when it does not, e.g. when the processor decodes a detailed video, which then plays in slow motion. |
| `decoder` | What decodes a video: `hardware`, the Pi 5's HEVC decoder, or `software`, the processor. |
| `warning` | What to change, for a video not in H.265. |
| `playlist` | While the playlist plays, which of its media is shown, `position`, from 1, or `null` if it is not played any more, and how many it has, `count`. Otherwise `null`. |

### Show a Medium, the Test Pattern or the Playlist

```
PUT /api/display
Content-Type: application/json
```

| Body | What it shows |
|---|---|
| `{"media_id": "8299c881"}` | The library's medium of this id. |
| `{"media_name": "helix_qs8x6a0.75.mp4"}` | The library's medium of this name. |
| `{"test_pattern": true}` | The test pattern: 48 views, each showing its number on a colour of its own. Through the lenses, one number fills the screen, and changes in order as we move sideways; a mix of numbers means that the calibration is wrong. With `"reverse": true`, its views in the other order. |
| `{"playlist": true}` | The [playlist](#the-playlist), from its first medium. |

The server shows a quilt, or plays a video in a loop, at its frame rate, and answers with [what is shown](#what-is-shown) once it is on the Looking Glass, a video's first frame too: on a Raspberry Pi 5, about 0.8 seconds for a quilt of 3360 x 3360, about 0.2 seconds for a video, as nothing is uploaded. It stays, also after a restart, until something else replaces it.

The playlist goes from one medium to the next by itself, until something else is shown, or black. The last picture stays until the next one is ready, which then comes with the playlist's transition. A medium's time counts from when it is on the Looking Glass. One that cannot be shown at all, e.g. as its file is damaged, is left out. Removing the medium shown goes on to the next. After a restart, the playlist starts again from its first medium.

| Status | When | Body |
|---|---|---|
| `200` | It is on the Looking Glass. | [What is shown](#what-is-shown). |
| `400` | Not one of `media_id`, `media_name`, `test_pattern` and `playlist`, or the playlist is empty. | An [error](#errors). |
| `404` | No medium of this id or name. | An [error](#errors). |
| `503` | It cannot be shown yet: no Looking Glass found, or no screen of its size. | An [error](#errors). It is kept, and shown as soon as it can be. |

A `503` is not a failure to retry: the server tries again by itself every 5 seconds, until it is shown or something else replaces it. `GET /api/display` says when it is shown.

### Show Black

```
DELETE /api/display
```

Shows black on the Looking Glass, and answers `204`. What was shown stays in the library. Through DRM/KMS, the server keeps the screen, black, until it stops; on a desktop, it closes its window. After a restart, the server shows its default quilt, if it has one.

## The Server

### The Status

```
GET /api/status
```

```json
{
  "version": "0.1.0",
  "screen": "gl",
  "looking_glass": {"serial": "LKG-PORT-00671", "width": 1536, "height": 2048},
  "calibration_error": null,
  "display": {"source": "media", "...": "as in What Is Shown"}
}
```

| Field | What it is |
|---|---|
| `version` | HoloPi's version. |
| `screen` | How it shows: `gl`, through the GPU, the container's; `drm`, straight to the screen; `desktop`, a full-screen window. |
| `looking_glass` | The Looking Glass's serial number and screen size, once its calibration has been read; `null` before. |
| `calibration_error` | Why the calibration could not be read, e.g. `no Looking Glass found: ...`, or `null`. |
| `display` | [What is shown](#what-is-shown). |

### The Calibration

```
GET /api/calibration
```

The values the interleaving derives from the Looking Glass's `visual.json`, as `holo-pi calibration` prints them; [The Calibration](ARCHITECTURE.md#the-calibration) explains each. `503` when the calibration cannot be read.

```json
{
  "serial": "LKG-PORT-00671",
  "width": 1536,
  "height": 2048,
  "pitch": 246.91001751815048,
  "tilt": -0.18618341023468643,
  "center": 0.7432299004945404,
  "subp": 0.00021701388888888888,
  "inverted": true
}
```

## Errors

Every error has the same body, with what went wrong and what to check:

```json
{"error": "no quilt or video of the name 'helix.mp4'"}
```

| Status | Meaning |
|---|---|
| `400` | The request cannot work, whatever the Looking Glass: not an image nor a video, no layout, a hologram video of another size, a name no file can have, a video to grade, no grade to save, seconds for a video or loops for a quilt, an empty playlist, or nothing to show. |
| `404` | No medium of this id or name. |
| `409` | Another medium has the new name. |
| `422` | A field is missing, of the wrong type or out of its range: `{"error": "invalid request: body.columns: ..."}`. |
| `501` | A video, and the server has no PyAV; or a grade, and the screen is not drawn by the GPU. |
| `503` | The Looking Glass is not ready: no calibration, no screen of its size, or the screen is held by a desktop. See [Troubleshooting](../README.md#troubleshooting). |

## Clients

### curl

```bash
# Upload a quilt, its layout in its name, and show it at once.
curl -F file=@helix_qs8x6a0.75.jpg -F play=true http://holo.local:8095/api/media

# Upload a quilt video without showing it, then show it by its name.
curl -F file=@helix_qs8x6a0.75.mp4 http://holo.local:8095/api/media
curl -X PUT -H "Content-Type: application/json" -d '{"media_name": "helix_qs8x6a0.75.mp4"}' http://holo.local:8095/api/display

# The library, and what is shown.
curl http://holo.local:8095/api/media

# The library in another order: every id, once.
curl -X PUT -H "Content-Type: application/json" -d '{"ids": ["c41d07aa", "8299c881", "3f9a1c2e"]}' http://holo.local:8095/api/media/order
curl http://holo.local:8095/api/display

# A quilt for 15 seconds, then a video twice, again and again.
curl -X PUT -H "Content-Type: application/json" -d '{"items": [{"media_id": "b44ef8ba", "seconds": 15}, {"media_id": "8299c881", "loops": 2}]}' http://holo.local:8095/api/playlist
curl -X PUT -H "Content-Type: application/json" -d '{"playlist": true}' http://holo.local:8095/api/display

# Black, then empty the library.
curl -X DELETE http://holo.local:8095/api/display
curl -X DELETE http://holo.local:8095/api/media
```

`curl --fail-with-body` makes a `4xx` or `5xx` an error of the command, with the message, for a script.

### Python

With `requests`:

```python
from pathlib import Path

import requests

SERVER = "http://holo.local:8095/api"


def upload(path, play=False, columns=None, rows=None):
    """Keeps a quilt or a video in the library. Returns its id; raises if it is refused."""
    fields = {"play": str(play).lower()}
    if columns and rows:
        fields.update(columns=str(columns), rows=str(rows))
    with open(path, "rb") as file:
        response = requests.post(f"{SERVER}/media", files={"file": (Path(path).name, file)}, data=fields,
                                 timeout=120)
    if not response.ok:
        raise RuntimeError(response.json()["error"])
    return response.json()["id"]


def show(id):
    """Shows a medium of the library. Returns what is shown; raises if it cannot be, yet."""
    response = requests.put(f"{SERVER}/display", json={"media_id": id}, timeout=30)
    if not response.ok:
        # 503: kept, the server shows it as soon as the Looking Glass is there.
        raise RuntimeError(response.json()["error"])
    return response.json()
```
